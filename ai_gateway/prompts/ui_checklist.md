# 任务

1. **归纳 UI 测试要点（aspect）**：把这个界面/应用"该测哪些方面"梳理成 6–12 个要点。要点应围绕**用户可操作的页面 / 流程 / 关键交互**组织，例如：
   - 页面级：某页面能正常加载、关键元素可见；
   - 流程级：登录 → 跳转工作台、下单 → 支付 → 完成等端到端流程；
   - 交互级：表单校验与提示、按钮 loading/置灰、弹窗/下拉/切换、列表分页/筛选/排序、空数据/加载失败态；
   - 断言维度：结构断言（元素存在/文案正确）、视觉断言（关键区域截图对比，若启用）。
   - **只归纳需求/上下文里真实存在的界面与交互**，不要编造不存在的页面。
   - 每个要点配一句 `what_to_test`：这一方面具体该验证什么。
2. **映射覆盖**：把上面「已有 UI 用例」逐条归到最合适的要点下，填进 `covered_cases`（**原样照抄用例名**）。一条用例只归一个要点；不属于任何要点的可忽略。
3. **给出缺口说明 `gap_hint`**：对**覆盖偏少或没覆盖**的要点，一句话具体说明**还缺哪些用例、建议补什么**（如"缺少表单必填校验提示、登录失败错误态两类交互用例"）；覆盖充分的要点 `gap_hint` 留空。
4. UI 自动化尤其要关注**可稳定定位/可执行**的交互——优先归纳有明确页面元素、能落成稳定脚本的测试点，不要归纳依赖不确定元素、无法可靠自动化的点。

# 输出格式（严格 JSON，只输出一个 ```json``` 代码块，不要任何额外文字）

```json
{
  "aspects": [
    {
      "aspect": "登录流程",
      "what_to_test": "输入合法账号密码点击登录 → 跳转对应工作台并显示用户信息",
      "covered_cases": ["登录成功跳转工作台"],
      "gap_hint": "缺少登录失败错误提示、密码框密文显示两类交互用例"
    }
  ]
}
```

约束：返回值是能被 `json.loads` 解析的合法 JSON 对象，含 `aspects` 数组；每个 aspect 含 `aspect`(字符串)、`what_to_test`(字符串)、`covered_cases`(字符串数组，可空)、`gap_hint`(字符串，覆盖充分时为空)。`covered_cases` 里的名称必须来自上面「已有 UI 用例」清单，不要编造。
