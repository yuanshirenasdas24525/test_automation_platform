# 任务

1. **归纳接口测试要点（aspect）**：把这些接口"该测哪些方面"梳理成 6–12 个要点。要点可以是**按接口分组**（如"登录接口 POST /api/auth/login"）或**按测试维度**（如"参数校验 / 鉴权与权限 / 越权 / 响应结构与状态码 / 边界与异常 / 幂等与并发 / 数据一致性"），选更贴合这批接口的组织方式。
   - **只归纳真实存在的接口与能力**：需求/上下文里没有的接口或维度不要编造。
   - 每个要点配一句 `what_to_test`：这一方面具体该验证什么（如"缺失/空/类型错误/超长等非法入参返回 4xx 且 message 明确"）。
2. **映射覆盖**：把上面「已有接口用例」逐条归到最合适的要点下，填进 `covered_cases`（**原样照抄用例名**）。一条用例只归一个要点；不属于任何要点的可忽略。
3. **给出缺口说明 `gap_hint`**：对**覆盖偏少或没覆盖**的要点，一句话具体说明**还缺哪些用例、建议补什么**（如"缺少 401 未授权、403 越权、429 限流三类响应校验"）；覆盖充分的要点 `gap_hint` 留空。
4. 不要遗漏这类接口通常必测的主干：正常调用、参数校验、鉴权/越权、响应结构与状态码。

# 输出格式（严格 JSON，只输出一个 ```json``` 代码块，不要任何额外文字）

```json
{
  "aspects": [
    {
      "aspect": "鉴权与越权",
      "what_to_test": "未带令牌 401、无权限 403、越权访问他人资源被拒、过期/伪造/篡改令牌拒绝",
      "covered_cases": ["【鉴权】未携带 token 访问返回 401"],
      "gap_hint": "缺少越权访问他人资源、篡改令牌两类用例"
    }
  ]
}
```

约束：返回值是能被 `json.loads` 解析的合法 JSON 对象，含 `aspects` 数组；每个 aspect 含 `aspect`(字符串)、`what_to_test`(字符串)、`covered_cases`(字符串数组，可空)、`gap_hint`(字符串，覆盖充分时为空)。`covered_cases` 里的名称必须来自上面「已有接口用例」清单，不要编造。
