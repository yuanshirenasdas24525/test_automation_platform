# 测试设计维度池（按覆盖力度取舍）

请先识别功能点、输入字段、操作、角色、状态，再按覆盖力度选择维度：

- 标准覆盖：每个功能点只保留主流程 + 最关键的异常/权限/边界风险，不要逐字段穷举。
- 全面覆盖：每个功能点、核心字段、核心操作都要系统覆盖，适用维度要有代表性测试点。
- 穷尽覆盖：才对每个功能点 / 每个输入字段 / 每个操作逐维度拆开，宁可多列、不要漏；不要为了简洁合并测试点，应尽量多规划可执行的独立点。

穷尽覆盖特别规则（只在覆盖力度为“穷尽覆盖”时生效）：

- 目标是在**上面「能力边界」允许的真实范围内**做到维度完整、逐字段逐操作拆细；「能力边界与禁止清单」始终优先于本节，越界内容再穷尽也不许列。
- 多拆的前提是"真实且可执行"；**不要为了让列表更长而编造点或把系统没有的能力也铺开**。
- 每个输入字段尽量分别拆出：必填缺失、为空、null、格式错误、类型错误、非法字符、首尾空格、超长输入、边界值。
- 每个核心操作尽量分别拆出：成功、失败、重复提交、取消/返回、刷新后状态、异常提示、权限不足、状态不允许、数据落库/联动。
- 页面交互、按钮状态、loading、二次确认、表单回显、列表刷新、分页/筛选/排序、空数据、大数据量可以作为独立点。
- 端到端流程要保留，同时允许拆出关键中间状态、失败分支、回滚/清理流程等多个场景点。
- 文档未给明确边界时，可以规划“探索性边界/鲁棒性”测试点，但标题中不要虚构具体业务规则。

维度池如下：

1. **正向**：主流程成功、典型有效输入、不同合法路径。
2. **等价类-无效**：每类非法输入各一条（为空、缺失、错误格式、非法字符、类型不符）。
3. **边界值**：最小/最大/刚好/超出、0/负数、长度边界（空串/1 字符/最大长度/超长）、首尾空格。
4. **异常与容错**：错误操作、重复提交、并发、网络中断/超时、依赖服务不可用、脏数据。
5. **权限/角色**：不同角色可见性与可操作性差异、越权访问、未登录/登录态失效。
6. **状态流转**：对象在各状态下的操作是否合法（如已删除/已禁用/已完成后再操作）。
7. **数据正确性**：操作后数据是否正确落库/更新/联动；列表筛选/排序/分页/统计正确性。
8. **跨模块联动**：与其它模块的依赖、数据共享、状态联动（见上方关联信息）。
9. **界面与交互**：必填校验提示、按钮置灰/loading、二次确认、取消、表单回显、刷新后保持。
10. **安全**：SQL 注入/XSS 等特殊字符、敏感信息是否脱敏、越权、重放。
11. **兼容/性能**（按需）：大数据量、特殊字符集、并发量。
