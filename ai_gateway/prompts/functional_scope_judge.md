# 判定规则

一个测试点属于**越界（out_of_scope）**，当它满足下列任一条：

1. **测的是本系统没有的功能**：上面能力上下文里从未出现、也无法从需求合理推断的功能。
   例如（若上下文未提及就算越界）：第三方登录 / SSO / OAuth / SAML / LDAP、双因素认证 / 短信或邮箱验证码、注册 / 忘记密码 / 记住我、密码复杂度或历史或过期策略、异地登录风控 / 设备指纹 / 登录地点时间提醒。
2. **不是功能用例**：运维 / 基建 / 部署架构（负载均衡、自动伸缩、多实例、熔断、限流、DDoS、WAF、容灾）、性能压测、合规（GDPR/CCPA/数据保留）。
3. **是过程或审计条目而非可执行用例**：文档完整性、代码质量、技术债、开源许可证、向后兼容 / 弃用策略检查。
4. **属于纯接口 / 协议层测试**（这类应走接口用例，不在功能用例里）。功能用例判定的是**用户可观察的业务行为**；如果一个测试点是站在 HTTP / 接口视角描述、脱离了用户在页面上能看到的结果，就判越界。典型信号（命中任一即倾向越界）：
   - 标题以"XX接口"为主语，断言的是 **HTTP 状态码**（返回 200/401/422/405/429…）而非页面表现；
   - 断言 **响应体结构 / 字段路径 / JSONPath**（如 `$.data.access_token`、响应信封 status 字段、user 对象路径）；
   - 校验 **Content-Type、请求方法(GET/POST)、请求体是否 JSON、参数类型/缺失返回 422** 这类协议层细节；
   - 关注 **令牌本身**（access_token/refresh_token 的结构、过期值 expires_in）而不是"用户被登出/需重新登录"这类可观察后果。
   
   反之，同样一件事若**从用户视角**描述则在范围内：例如"密码错误时页面提示'用户名或密码错误'且停留登录页"in_scope，而"登录接口错误密码返回401且detail为'用户名或密码错误'"out_of_scope（协议层，应走接口用例）。

一个测试点属于**在范围内（in_scope）**：它验证的是上面能力上下文里真实存在的页面、控件、业务规则、角色、状态流转或其正/反/边界分支——**即使它是异常、边界、安全（如登录框注入、越权提示、会话失效后跳登录页）用例也算在内**，只要它描述的是**用户在页面上可观察的**结果，且针对本系统真实的输入面和鉴权点。

**已声明业务规则优先保留（重要）**：如果一个测试点验证的是上面能力上下文里**明确写到的业务规则**（例如"连续5次密码错误锁定约5分钟""单Web会话唯一，新登录踢旧""修改密码后全端下线""内置admin不可停用"），那么**即使它措辞偏抽象、偏后端规则、没有逐字写出页面步骤，也判为 in_scope**——只要它对应的是真实存在的规则、且能落成用户可观察的验证（如"账号被锁定后无法登录"）。不要因为措辞不够"页面化"就把已声明的核心规则判越界。只有当它**同时**是接口/协议层措辞（断言 HTTP 状态码 / JSONPath / 令牌结构等）时才判越界。

拿不准时**倾向保留（in_scope）**——宁可多留，不要误杀真实场景；已声明的业务规则尤其要留。
