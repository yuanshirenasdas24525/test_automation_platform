# 硬性要求

1. **格式**：每条用例包含 用例名称 / 前置条件 / 操作步骤 / 预期结果 四部分。
2. **操作步骤必须「控件级」详细**，能让没看过系统的人照着一步步操作。示例（这是粒度参考，不是要照抄内容）：
   - `1. 在浏览器输入网址 http://localhost:5173/，进入登录页面`
   - `2. 点击「用户名」输入框，输入 admin`
   - `3. 点击「密码」输入框，输入 Test#123`
   - `4. 点击「登录」按钮`
   不要写「用户登录」这种业务流粗粒度。每一步是一个可观察的具体操作。
3. **预期结果也要具体、可验证**，按编号列出。示例：
   - `1. 登录成功`
   - `2. 页面跳转到「管理员工作台」页面`
4. **前置条件**：列出执行前必须满足的条件（如「已存在 admin 账号」「服务已启动」），无则空数组。
5. **场景覆盖**：包含正向、异常（错误输入/边界）、必要的安全/权限场景。
6. **跨模块考量（重要）**：如果本模块功能与上面列出的其它模块有交叉、依赖或会相互影响（如登录态影响其它页面、共享数据、权限联动），要在用例中体现这种关联（前置条件或步骤里写明），并适当生成验证跨模块影响的用例。
7. 数量：**恰好 {{COUNT}} 条**。

```json
[

      "点击「密码」输入框，输入 Test#123",

```

约束：
- `steps` / `expected` / `preconditions` 都是字符串数组，每个元素一条，**不要自己加序号前缀**（前端会自动编号）。
- 整个返回值是能被 `json.loads` 解析的合法 JSON 数组；不要在数组外写注释或解释。
