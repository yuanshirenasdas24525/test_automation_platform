# 任务

1. **归纳测试要点（aspect）**：把这个功能"该测哪些方面"梳理成 6–10 个要点。每个要点是一个**面向业务的测试维度**（例如登录功能可能有：能否登录 / 输入校验与错误提示 / 失败锁定 / 会话与续期 / 修改密码 / 权限与角色跳转 / 安全 / 界面反馈）。
   - **只归纳这个系统真实存在的能力**：需求/说明里没有、也无法合理推断的功能（如第三方登录、验证码、注册——若未提及）**不要列**。
   - 每个要点配一句 `what_to_test`：这一方面具体该验证什么。
2. **映射覆盖**：把上面「已有用例」逐条归到最合适的要点下，填进该要点的 `covered_cases`（**原样照抄用例名**）。一条用例只归一个要点；实在不属于任何要点的可忽略。
3. 不要为了凑数编造要点，也不要遗漏需求里明确写到的主干规则（如"失败锁定""改密后全端下线""按角色跳不同工作台"）。

# 输出格式（严格 JSON，只输出一个 ```json``` 代码块，不要任何额外文字）

```json
{
  "aspects": [
    {
      "aspect": "失败锁定",
      "what_to_test": "连续多次密码错误后账号被锁定、锁定期间正确密码也进不去、到时自动解锁、仅锁该来源",
      "covered_cases": ["【安全】连续5次密码错误后账号被锁定约5分钟"]
    },
    {
      "aspect": "界面反馈",
      "what_to_test": "登录中按钮 loading、空输入置灰、失败后输入框保留或清空",
      "covered_cases": []
    }
  ]
}
```

约束：返回值是能被 `json.loads` 解析的合法 JSON 对象，含 `aspects` 数组；每个 aspect 含 `aspect`(字符串)、`what_to_test`(字符串)、`covered_cases`(字符串数组，可为空)。`covered_cases` 里的名称必须来自上面「已有用例」清单，不要编造。
