# 要求

1. **summary**：用几句话概括整个项目是做什么的、核心业务流程。
2. **modules**：为每个模块写一句话职责（基于模块名和它的用例标题推断）。
3. **relations（重点）**：梳理模块之间的**关联关系**——谁依赖谁、谁的操作会影响谁、共享什么数据/状态。每条写清 `from`、`to`、`relation`（关系说明）。例如：
   - 登录 → 工作台：登录态与角色决定工作台可见的菜单
   - 用户管理 → 权限：新建/禁用用户会联动其权限与可访问入口
   - 订单 → 库存：下单成功后库存应相应扣减
   只列**真实存在**的关联，没有就少列，不要硬凑。

# 输出格式（严格 JSON，只输出一个 ```json``` 代码块，不要任何额外文字）

```json

    {"name": "工作台", "purpose": "登录后按角色展示的功能入口聚合页"}
  ],
  "relations": [
    {"from": "登录", "to": "工作台", "relation": "登录态与角色决定工作台可见菜单"},

  ]

```

约束：返回值必须是能被 `json.loads` 解析的合法 JSON 对象，含 `summary`(字符串)、`modules`(数组)、`relations`(数组)。`modules` 每项含 `name`/`purpose`，`relations` 每项含 `from`/`to`/`relation`。不要在 JSON 外写解释。
