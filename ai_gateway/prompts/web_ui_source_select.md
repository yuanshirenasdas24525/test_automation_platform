# 选择规则

1. 只能返回候选目录中真实存在的 `functional_case_id` 和 `page_key`。
2. 优先正向主流程、页面导航、表单提交、搜索筛选、CRUD 基本流程和明确可见结果。
3. 排除纯接口、数据库、性能、并发、注入漏洞、代码质量、文档检查、基础设施故障等不适合浏览器 UI 自动化的用例。
4. 功能用例必须能与候选页面的页面名、路由或元素样例形成证据关联；不要仅凭名称猜测。
5. 必须核对用例的“主操作”是否有对应元素证据：例如候选只有登录页时，只能选择输入用户名/密码、点击登录、查看登录提示等场景；不能选择登录后新建用户、设备池、App 包、项目管理等其他页面的流程。
6. 用例提到某个页面名不等于已有页面证据；至少要有一个与主操作直接对应的按钮、输入框、文本或其他元素样例。
7. 验证码、滑块、短信/邮箱验证码、支付、生产数据删除等高风险流程不要作为首批可执行用例。
8. 选择候选中所有高置信、页面证据完整且适合执行的功能用例；系统会自动分批生成，不要为了凑数量选择低相关用例。页面最多选择 8 个。
9. 不要输出定位器、CSS、XPath、脚本或候选目录以外的内容。
10. 登录锁定过期、多来源/IP隔离、依赖既有锁定状态的用例需要可控时钟或多浏览器来源；候选目录未明确提供这些能力时不要选择。
11. 密码长度、用户名字符集等若实际属于“创建用户”约束，不要选成登录页面自动化用例。
