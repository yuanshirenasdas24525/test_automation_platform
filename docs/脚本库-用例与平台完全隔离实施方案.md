# 脚本库：用例与平台完全隔离实施方案

## 目标

API、Web、Android、iOS 用例不得通过修改平台 Python 文件获得项目能力。账号准备、
动态数据、签名、外部服务调用、复杂断言和清理逻辑统一保存在项目脚本库中。

平台代码只保留四类通用能力：步骤调度、JSON 变量传递、报告聚合、脚本进程管理。

## 已实施边界

```text
用例 JSON / 数据库脚本
        │ JSON
        ▼
通用 ScriptStepRunner
        │ stdin/stdout JSON
        ▼
一次性隔离 Python 进程
        │ HTTP / DB SDK / 第三方包
        ▼
被测系统
```

- 平台 API、Celery Worker 不再 `exec` 或 import 项目脚本。
- 子进程使用 `python -I`，工作目录是临时目录，不能 import `server`、`database`、
  `runners` 等平台源码包。
- 平台数据库连接、JWT、数据库密码等环境变量不会传入脚本进程。
- 变量、输入、配置和输出都必须可 JSON 序列化；浏览器对象、ORM、数据库连接不会跨边界。
- 每次调用启动独立进程；超时会终止整个进程组，不残留模块全局状态。
- 脚本可 import 当前运行环境已安装的包。
- 脚本页面可以声明独立 pip 依赖。依赖按 Python 版本、操作系统、CPU 架构和依赖集合
  缓存到 `data/script_runtimes/`，不会修改平台 `requirements.txt`。
- `function:xxx()` 只查脚本库；`utils/function_executor.py` 不再包含项目函数回退。

## 脚本类型

| 类型 | 用途 | handler |
|---|---|---|
| `function` | 参数动态值 | `handler(*args, vars=None, ctx=None)` |
| `workflow` | 项目流程、数据准备、断言、清理 | `handler(input, vars=None, config=None)` |
| `crypto_request` | HTTP 请求加密/签名 | `handler(headers, body, config, vars=None)` |
| `crypto_response` | HTTP 响应解密 | `handler(response_body, config, vars=None)` |

`workflow` 是四种自动化类型共用的正式 `script` 步骤，也可以放进可见的前置/后置步骤。

## workflow 返回协议

```python
def handler(input, vars=None, config=None):
    return {
        "ok": True,
        "result": {"user_id": 123},
        "variables": {
            "username": "AUTO_UI_123",
            "password": "Test#123",
        },
        "logs": ["测试账号创建完成"],
    }
```

- `ok: false`：步骤按断言失败处理。
- `variables`：写回当前用例变量池，后续步骤用 `${username}` 引用。
- `result`：配置 `save_result_as` 后可整体保存到一个变量。
- `logs`：写入执行上下文日志。
- `raise AssertionError(...)`：业务失败。
- 其他异常：执行错误，并保留子进程 traceback。

## 账号工厂示例

账号创建接口属于项目逻辑时，在项目脚本库新建 `workflow`，不要新增
`server/services/*_account.py`。在“项目配置 → Web → test_accounts”中设置：

```text
provider = script
prepare_script = project_account_factory
cleanup_script = project_account_factory   # 可留空，默认复用 prepare_script
script_config = {"tenant":"qa"}
```

AI Web 用例的账号准备会自动调用该脚本；普通 API/Web/Android/iOS 用例也可以
直接添加 `script` 步骤调用同一个 workflow：

```python
import httpx

def handler(input, vars=None, config=None):
    if input["action"] == "cleanup":
        with httpx.Client(base_url=config["api_base_url"], timeout=20) as client:
            client.delete(f"/api/users/{input['token']['user_id']}").raise_for_status()
        return {"ok": True, "logs": ["临时账号已清理"]}

    account = input["account"]
    with httpx.Client(base_url=config["api_base_url"], timeout=20) as client:
        login = client.post("/api/auth/login", json={
            "username": config["admin_username"],
            "password": config["admin_password"],
        })
        login.raise_for_status()
        token = login.json()["data"]["access_token"]
        created = client.post(
            "/api/users",
            headers={"Authorization": f"Bearer {token}"},
            json=account,
        )
        created.raise_for_status()
        user = created.json()["data"]
        return {
            "variables": {
                "username": user["username"],
                "password": account["password"],
            },
            "result": user,
            "cleanup": {"user_id": user["id"]},
        }
```

脚本所需的 `httpx` 等依赖在脚本编辑页填写，例如 `httpx==0.28.1`。依赖安装在
脚本独立缓存中，不修改平台环境。清理可以使用另一条 workflow，也可以像示例一样
让同一个脚本按 `input.action` 分派。

## 不变量

1. 新测试需求不得向 `server/services`、`runners`、`utils` 添加项目专用函数。
2. 新项目逻辑只能通过脚本库、HTTP 步骤或已有通用 step type 表达。
3. 新 step type 只能代表跨项目通用能力，不能以项目名、接口名或某条用例命名。
4. 脚本不得依赖平台 ORM、Session、浏览器驱动对象或内部模块。
5. 项目脚本缺能力时，优先扩展脚本协议或独立依赖能力，而不是把逻辑写回平台进程。
