# 本次会话产出总览

> 2026-07 | 主线:提升 AI 用例生成质量,把"生成→评审→执行→自愈"做成闭环。
> 约 1600 行新代码 + 多处改造 + 若干设计文档与运维脚本。

## 一、一句话主线

从聊项目价值/商业化定位起步,收敛到一条工程主线——**让 AI 生成的测试用例首次就尽量对、
越用越准、垃圾进不了评审页**,并为"AI 时代的验证层"铺路(MCP)。

## 二、按主题分组的改动

### 1. 生成前上下文注入(让 AI 有据可依,不凭空猜)
- **记忆层注入**:生成用例前检索 `project_contexts`(业务规则/数据模型/API 契约/术语/流程/约束),
  注入 M7 与大纲两条生成链路。`case_generation_context_builder.py` / `functional_cases.py` / 多个 prompt。
- **few-shot 样例 + 反例**:同模块已采纳草稿作正例、被拒草稿+拒因作反例,一起注入。
- **接口 batch 步骤补注入**:修复"extract/assertion 照 prompt 假惯例猜 JSONPath"导致首跑仅 17% 的问题。
- **prompt_version 升 v2**,便于按版本对比采纳率。

### 2. 草稿质量把关(垃圾不进评审页)
- **静态校验 + AI 自修回路**:`draft_validation.py`;不合格草稿先让模型自修,仍不合格丢弃。
- **草稿去重**:`dedup_against_existing`(标题归一化 + difflib),剔除与同模块已入库用例近乎重复的。
- **写入后一键试跑** + 评审页"已自动修复 / N 处提醒"徽标(前端)。

### 3. 评审界面与数据飞轮
- **M7 草稿评审对话框** `CaseGenerationReviewDialog.tsx`:生成→评审→采纳/拒绝(带原因)。
- **评审信号埋点**:`original_payload` 快照、`edit_ratio` 编辑相似度、`reject_reason`;
  统计端点 `GET /api/ai/case-drafts-stats`(采纳率/编辑距离/top 拒因,按模型与 prompt_version 分组)。
  迁移 `20260710_0003_ai_case_draft_review_signals.py`。

### 4. 事实回流(运行/分析暴露真相 → 入记忆 → 下次生成对)
- **分析文档回流**:`requirement_analyze` 完成后提取事实条目写记忆层。`context_extraction.py`。
- **响应约定自动回流**:api 报告跑完自动从真实响应提炼结构约定入库(带 7 天节流)。
  `response_convention.py` + `learn_convention_task.py`,挂在 `run_test_task` 收尾。
  → **新项目零人工介入,首跑后自动开窍。**

### 5. 会话隔离(根治 token 被登出作废的连环 401)
- **pre_hook 前置登录**:需登录态的用例自带登录拿专属 token,不受前序用例登出/改密污染。
  生成层(`interface_case_batch.md` + `_shape_cases` + 前端 `toInterfaceCase`)与
  修复层(`ai_fix_service.py` 支持 `fix.pre_hook` + 诊断 prompt 规则 7.3)双管齐下。
- **会话作废类用例自我隔离规则(8.3.1)** + **单会话模型识别** + **管理接口缺鉴权启发式告警**。

### 6. 覆盖率视图(把"补全面"变成可点动作)
- `coverage_service.py` + `GET /api/requirements/coverage`:按需求列用例/草稿/缺口分级,缺口高优先排前。
- 前端 `CoverageDialog.tsx`:需求页"覆盖率"按钮,缺口需求一键跳生成。

### 7. 战略文档(MCP)
- `docs/方案-MCP-server草案.md`:把执行/报告/用例能力包成 MCP,让 coding agent 直接调用。
